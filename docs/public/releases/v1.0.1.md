# Wakeplane v1.0.1

This patch fixes slow global run-history reads as the ledger grows. The operator console and integrations that load schedules together with recent runs can now use an index matching Wakeplane’s normalized timestamp ordering.

SQLite and Postgres migration 004 adds the normalized run-history index. It preserves RFC3339Nano chronology, ID tie ordering and cursor pagination. The migration recognizes an existing index with the same name, including the separately repaired Pi Durable installation.

## Upgrade

Drain active work and preserve a consistent database-native backup together with runner state before replacing binaries. Start one daemon per database and retain the previous binaries and backup for rollback. Startup applies the additive index migration. Existing schedules and stored run history remain intact.

## Verification

The source fix passed SQLite migration, query-plan, mixed timestamp and pagination regressions, the full Go suite and real Postgres store tests. The affected installation’s recent-run API and installed companion overview also passed after its separately approved repair. Release CI verifies the tagged build and published archives separately.
